The Problem
Why Deserving Students Lose Financial Aid

in state and central scholarships go unclaimed or rejected every year — not because students don't want them, but because navigating government portals feels like preparing for the civil services exam.

15+ Overlapping Schemes
Tamil Nadu runs 15+ welfare & scholarship schemes across ADW, BC/MBC Welfare, Pudhumai Penn, 7.5% Quota — each with hyper-specific thresholds across community, income, gender, and more.
📄
Information Overload
A student cannot read 15 separate 40-page government gazette orders to know what they qualify for. There is no single unified source that aggregates all criteria.
⚠️
The "Conflict Trap"
Students can't draw from two overlapping schemes simultaneously. Apply to both → both get rejected. Or they pick a ₹4K scheme when eligible for a ₹40K bundle.

The Solution
SchemeMatch — An Algorithmic Scholarship Counselor
🤖
Zero-Barrier AI Profiling
Student types: "I'm a girl from a TN govt school, doing B.Tech, 1.2 LPA, BC" — our NL parser extracts all parameters instantly. Dual-mode: LLM primary + deterministic regex fallback.
📋
30+ Audited Scheme Catalog
19 Tamil Nadu + 11 National schemes, each coded with exact departmental criteria as deterministic eligFn() functions. Rule-based — zero hallucinations.
⚡
Conflict-Aware Decision Engine — The Core Innovation
Doesn't dump 8 random schemes. Models schemes as a weighted conflict graph. Solves the Maximum Weight Independent Set (MWIS) problem to find the highest-value, legally valid, non-conflicting combination. Uses bitmask brute-force (n≤20, <50ms) with greedy fallback. AI only phrases results — never decides eligibility.
Algorithm Pipeline
From Natural Language to Optimal Aid Bundle in <50ms
Each scheme has exclusiveGroup and conflictsWith metadata mirroring real NSP "one benefit per fee line" rules.
NL Input → AI Parse → 30+ eligFn() → MWIS → ₹ Best Combo

Scalability
Built to Scale — From Tamil Nadu to All of India
📝
Declarative JSON Rule Schema
Scheme rules are not hard-coded in logic. Eligibility conditions, income ceilings, community gates, and conflict edges are parameterized in JSON. Adding a new scheme takes 2 minutes — change a config file, no code redeployment needed.
🔄
Auto-Ingestion Pipeline
Daily cron job crawls official government portals (HTML + PDF), extracts structured data via LLM, and proposes updates. High-confidence extractions auto-apply; medium/low go to human review queue with full audit trail.
🌍
State-Agnostic Architecture
TN-specific categories (BC/MBC/DNC) are in the data layer, not the engine. Adding Karnataka, Maharashtra, or any state is just adding a new stateSchemes.js file with eligFn definitions — same engine, same conflict resolution.
🔌
API-First Design
RESTful backend with POST /schemes/match and POST /profile/parse endpoints — can be plugged into TN e-District, UMANG, Naan Mudhalvan, or any govt portal with a single API webhook.
